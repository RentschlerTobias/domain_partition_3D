## 6. Key pitfalls

- Pitfall: `--cell-quaternion-in-path` is a NO-OP — do not lean on it.
- Pitfall: recover from AlgoHex timeouts with `--save`/`--load-param-state` on the patched binary (`/work/tools/algohex-size/build/Build/bin/HexMeshing`); a saved param state replays cleanly (P1 did exactly this).
- Pitfall: the AlgoHex parametrization is MUMPS-bound → give it 8–16 cores and a timeout of 28800 s; single-core runs die at the wall (10800 s, exit 124); sweeps pin every run with `--cores` (defaults `$CALIB_CORES`, else "0,1") and each sample needs its own pinned core pair.
- Pitfall: never wait with `while pgrep -f <pattern>` — the pattern matches the waiting shell itself; it cost two silent 20-minute stalls (HANDOFF.md).
- Pitfall: `/work` is not a git repo — collectors/code go to `experimentell/hex3d_algohex/`, artifacts may stay under `/work`.
- Pitfall: `/opt/venv-sci` has no vtk module — the VTK writers emit legacy VTK by hand (canada_export_vtk.py, export_features_vtk.py).
- Pitfall: `beam_collapse` does a double collapse (plus pre-eval waste); backlog `beam-collapse-remove-double-collapse-and.md` estimates ~30–50 % faster without it.
- Pitfall: ADMM/HexEx is not bit-reproducible (n2000/replay logs hold two attempts with different valid_volume) — compare via the `--check` reports, not byte equality.
