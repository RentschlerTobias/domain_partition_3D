# The pipeline in 11 steps

The 3D counterpart of the 2D showcase (`dp3d/plotting.py` →
`output/plots/step01…step11`). Generated by `showcase.py`, output in
`output/hex3d_algohex/showcase/`.

Every step is written **three ways from one description**, so they cannot
drift apart:

| | what it is for |
|---|---|
| `.vtk` | **the authoritative artifact.** A 3D block structure is not legible in a flat render — this is what you open in ParaView to actually check something |
| `.png` | fixed-camera render (pyvista, off-screen), for skimming the series |
| `.html` | the same scene as an interactive plotly figure, self-contained, embeddable in slides |

```bash
PY=/root/repos/duty/quadmesh/.venv/bin/python
$PY experimentell/hex3d_algohex/showcase.py --steps all --tag v11
$PY experimentell/hex3d_algohex/showcase.py --steps 4,10        # single steps
```

Requires `pyvista` and `plotly` (`uv pip install --python .venv/bin/python
pyvista plotly` from `/root/repos/duty/quadmesh`). Rendering falls back to
OSMesa; no X server is needed.

## The metrics, each with what it actually caught

Not a glossary. Every row names the function and a real result.

| metric | implementation | what it caught |
|---|---|---|
| scaled Jacobian (min over 8 corners) | `ovm_io.scaled_jacobian`, vectorised as `clean_blocks.scaled_jacobians` | v5 has 96 inverted cells against v9's 2 — the reason v9 became the base |
| hex volume | `ovm_io._hex_volume` | the corrected version turned a reported "31.4 % coverage" into 95 %; the buggy variant is still live in `hexa_interpolation.py` |
| coverage = Σ cell volume / domain volume | census script | v11 5.4688 against the domain's 5.4606 |
| singular edges, arcs, valence | `base_complex.singular_edges` + arc walk | v5 308 edges / 12 arcs against v11 164 / 6 |
| arc endpoints per surface | `showcase._singular_graph` | all four runs have exactly 2 on the outlet — this killed the "cutting the layer causes it" hypothesis |
| boundary components | `clean_blocks.boundary_components` | 3 instead of 1 on v9 = two internal cavities, 28 and 22 quads, 14 missing cells |
| faces per block | `clean_blocks.cuboid_status` | v11 {6: 115, 7: 2} against v9 {6: 72, 7: 4, 8: 4, 9: 3, 10: 1, 12: 1} |
| excess faces, Σ max(0, faces − 6) | `clean_blocks._excess` | replaced a non-cuboid *count* that had built 17- and 27-faced blocks while the percentage rose |
| Hausdorff to the input surface | `HexBlockValidator.boundary_hausdorff` | v11 0.0341 against v9 0.1851 — the label fix, not the postprocessing |
| block-edge kink angle | `clean_blocks.edge_kink_stats` | 63 kinks above 30°, 45 of them on 14 `shell_hub\|shell_blade` curves |
| interface gap | `reattach.interface_gap` | 0.0418 median — the non-conformity assumption checked instead of assumed |

Where a distribution exists, the figures show the distribution, not only the
extremum. This branch has been burned five times by a mean or a single
extremum moving the right way while the structure got worse (PROGRESS.md,
"Stage 5c").

## Two bugs the showcase itself turned up

**`pv.PolyData(points)` makes a vertex cell per point.** Setting `.lines`
afterwards leaves those in, so `n_cells` is points + lines and every cell
array is rejected for the wrong length. Fixed by passing `lines=` to the
constructor.

**`hex_grid()` returns a grid that shares the caller's point array, and
`translate(inplace=True)` then moves the caller's data.** In step 10 that
silently shifted the mesh feeding the next collapse round: round 3 came out
with 2 cuboids instead of 14, because its surface labels were transferred at
coordinates offset by 4.2. The small-multiple offset is now applied to a copy
used for rendering only, and the saved VTK is never translated — a file
called data has to be data. With the fix the replay reproduces the recorded
rounds exactly, cuboids 28 / 19 / 14 and inverted 12 / 3 / 2.
